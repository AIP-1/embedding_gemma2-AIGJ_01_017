## 설치 스크립트 (.sh)

학생 여러 명이 한 Jetson을 각자 계정으로 쓰기 때문에, 장비 공통 설정(system)과 계정별 설정(user)을 두 파일로 나눴다. 두 스크립트 모두 이미 된 항목은 건너뛰므로 다시 실행해도 안전하다.

### system_setup.sh — 장비당 1회, 관리자가 sudo로

사용법: `sudo bash system_setup.sh 계정1 계정2 ...`

1. 시스템 패키지 설치: python3-venv(가상환경 만드는 도구), ffmpeg(영상·음성 변환), libsndfile1(음성 파일 읽기) 등. 모든 계정이 공유하므로 한 번만 설치한다.
2. 최대 성능 모드: `nvpmodel -m 0`, `jetson_clocks`로 전력 제한을 풀고 클럭을 고정해 측정값이 흔들리지 않게 한다.
3. 스왑 8GB: 램이 8GB라 모델을 올리다 메모리가 부족하면 죽는 것을 막는다. SSD가 있으면 /ssd/swapfile에 만든다.
4. 공용 모델 폴더 /ssd/hf: 모델(수 GB)을 계정마다 받지 않도록 한 곳에 두고, aiplab 그룹이 함께 읽고 쓸 수 있게 권한을 준다.
5. 계정을 aiplab(공용 모델 폴더)·video(웹캠) 그룹에 추가한다. 다시 로그인해야 적용된다.

### user_setup.sh — 계정당 1회, 본인이 sudo 없이

사용법: `bash user_setup.sh` (system_setup.sh 실행과 재로그인이 먼저)

1. 사전 조건 확인: ffmpeg·python3-venv가 없으면 "관리자가 system_setup.sh 먼저"라고 알리고 멈춘다. Python 버전으로 JetPack 6/7을 판단한다.
2. 모델 캐시 위치(HF_HOME): /ssd/hf에 쓸 수 있으면 공용 폴더를, 아니면 개인 폴더를 쓰도록 ~/.bashrc에 적는다.
3. 가상환경 ~/eg2 만들기: 이 계정만 쓰는 Python과 패키지 공간.
4. Jetson용 PyTorch 설치 (JetPack 7은 cu132 휠). GPU에서 행렬 곱셈을 한 번 돌려 확인한다.
5. sentence-transformers 설치: torch 버전을 고정해 두고 설치해서 Jetson torch가 일반 torch로 덮어쓰이지 않게 한다. JetPack 7에서는 충돌하는 torchaudio를 지운다(README Q7).
6. 실습 폴더 ~/eg2-lab을 만들고 check.py·eg2.py를 생성한 뒤 check.py를 실행한다.
7. 단축 명령 `eg2`를 ~/.bashrc에 등록한다.
8. 모델을 받고(공용 폴더에 있으면 생략) 한 번 로드해 (768,)이 나오는지 본다.

### jetson_setup.sh — 예전 통합본 (지금은 쓰지 않음)

README 1·2단계를 한 파일로 하던 첫 스크립트다. 내용은 위 두 파일을 합친 것과 같고, 계정 하나만 쓸 때를 가정해 공용 모델 폴더·그룹 설정과 `eg2` 단축 명령이 없다. 여러 학생이 쓰게 되면서 두 파일로 나눴다.

## 실습 코드 (.py)

모든 .py 파일은 ~/eg2-lab에 둔다. 실행 전에 venv를 켜야 한다(`eg2` 입력 또는 `source ~/eg2/bin/activate`).

### check.py — 설치 확인

torch·transformers·sentence-transformers 버전을 출력하고, torch가 GPU(CUDA)를 쓸 수 있는지 검사한다. GPU를 못 쓰면 에러로 멈춘다. 패키지를 설치하다 Jetson용 torch가 일반 torch(GPU 없는 버전)로 덮어쓰이는 사고를 잡기 위한 파일이다. 실행: `python check.py`

### eg2.py — 모델 불러오기 공통 코드

직접 실행하는 파일이 아니라, 다른 .py가 `from eg2 import load`로 가져다 쓴다. 그래서 같은 폴더에 있어야 한다.

- `load()`: EmbeddingGemma 2 모델을 GPU에 올려 돌려준다.
- `load(vision=True)`, `load(audio=True)`: 영상·음성 인코더도 함께 올린다(4·5단계). 기본값은 텍스트 전용이라 메모리를 아낀다.
- bfloat16으로 불러온다. float16은 결과가 깨져서 금지.

### test_text.py — 3단계 텍스트 검색 테스트

문서 4개와 한국어 질의 2개를 임베딩(숫자 벡터)으로 바꾸고, 질의마다 가장 비슷한 문서를 고른다. 고르는 건 사람이 아니라 프로그램이다: 질의 하나와 문서 4개 사이의 유사도 점수(0~1, 클수록 뜻이 비슷함)를 계산하고, 점수가 가장 높은 문서를 1위로 출력한다. 질의와 정답 문서는 겹치는 단어가 거의 없어서, 정답이 1위면(정답 = 사람이 미리 정해 둔 짝: 첫 질의는 CO2 문장, 둘째 질의는 에어컨 문장. 이 문장이 점수 1등으로 나오면) 모델이 의미로 찾고 있다는 뜻이다.

- 문서는 `Document`, 질의는 `SearchQuery` 프롬프트로 나눠 임베딩한다.
- 벡터 길이를 768 → 256 → 128로 줄여 가며 같은 검색을 반복해, 줄여도 정답이 유지되는지와 질의 임베딩 시간(ms)을 본다.
- 기대 결과: 첫 질의 → CO2 문장, 둘째 질의 → 에어컨 문장이 모든 길이에서 1위. 첫 길이(768)는 준비 시간이 섞여 느리므로 속도 비교는 256부터 한다.
- 실행: `python test_text.py`

### test_vision.py — 4단계 사진·영상 검색 테스트

3단계의 '문서(글)' 자리에 사진과 동영상을 넣은 것이다. 모델이 글과 사진을 같은 768개 숫자 벡터로 바꾸므로, 질의(글)와 사진의 유사도를 계산해 점수가 높은 사진을 1위로 출력한다.

- 준비물: ~/eg2-lab/media/ 에 사진 3~5장(.jpg/.jpeg/.png)과 동영상 clip.mp4(10초 내외, 없어도 됨).
- `load(vision=True)`로 비전 인코더까지 올린다. 3단계보다 로딩이 느리고 메모리를 더 쓴다.
- 출력: 사진·동영상 임베딩 시간, 질의마다 상위 3개 사진과 점수, 질의별 동영상 점수, GPU 메모리 최대 사용량.
- 동영상은 기본 방식(torchcodec)으로 먼저 읽고, 실패하면 PyAV(`pip install -c ~/eg2/torch-pin.txt av`, 내 venv에만 설치)로 1초에 1장씩 꺼내 넣는다. 이 Jetson은 NVIDIA판 FFmpeg에 libswscale이 없어 torchcodec이 안 되므로 PyAV 경로를 쓴다. 출력의 `[방식: ...]`으로 확인.
- 둘 다 실패하면 이유를 한 줄 찍고 사진 결과는 끝까지 낸다.
- 질의 3개(빈 강의실 / 수업 중 / 화이트보드 글씨)는 코드 안 `queries`에서 내 사진에 맞게 바꿀 수 있다.
- 실행: `python test_vision.py`

### make_sounds.py — 5단계 경보음·잡음 만들기

README의 `ffmpeg -f lavfi ...` 명령을 대신한다. 이 Jetson의 NVIDIA판 FFmpeg는 소리 생성 기능(lavfi)을 빼고 빌드돼 `Unknown input format: 'lavfi'` 오류가 난다. numpy로 1 kHz 사인파 3초(beep.wav)와 핑크 잡음 5초(noise.wav)를 계산해 soundfile로 16 kHz 모노 wav로 저장한다. venv에 이미 있는 패키지만 써서 설치할 것이 없다. 실행: `python make_sounds.py`

### test_audio.py — 5단계 음성·소리 검색 테스트

4단계의 사진 자리에 소리 파일(.wav)을 넣은 것이다. `load(audio=True)`로 오디오 인코더를 올리고, 질의(글)와 소리의 유사도를 계산해 점수가 높은 파일을 1위로 출력한다.

- 준비물: ~/eg2-lab/media/ 에 speech.wav(말소리), beep.wav(경보음), noise.wav(잡음). mic.wav(직접 녹음)는 선택. 이름이 raw_로 시작하는 파일은 변환 전 원본으로 보고 뺀다.
- 말소리는 맥북 `say`로 만들어 scp로 보내면 Jetson에 아무것도 설치하지 않아도 된다. README의 espeak-ng는 `sudo apt`(장비 전체)가 필요하다. 경보음·잡음은 make_sounds.py로 만든다(아래).
- 모델은 16 kHz 모노만 제대로 읽는다. 형식이 다른 파일은 librosa(venv에 설치돼 있음)가 메모리 안에서 바꿔 넣으므로 ffmpeg로 다시 변환할 필요가 없다. 파일마다 원본 형식과 변환 여부를 한 줄씩 찍는다.
- 넣는 방식은 파일 경로(기본) → librosa 배열 → 배열+샘플레이트 순으로 시도한다. 4단계처럼 장비 FFmpeg 때문에 기본 방식이 실패해도 배열 방식은 FFmpeg를 쓰지 않는다. 출력의 `[방식: ...]`으로 확인.
- 출력: 파일별 형식, 오디오 임베딩 시간 1·2회차(6단계 표에는 2회차), 질의마다 전체 순위와 점수, GPU 메모리 최대 사용량.
- 기대 결과: 덥다는 목소리 → speech, 경보음 → beep, 배경 소음 → noise가 1위.
- 이 Jetson 결과(v1): 기본 방식은 torchcodec 오류로 실패, librosa 배열로 동작. 경보음·소음은 맞고, 덥다는 목소리는 noise 0.651 / speech 0.647로 근소하게 틀림. v2에 '사람이 말하는 목소리'(말소리인지)와 '에어컨을 켜 달라는 말'(말의 내용) 질의를 더해 어디서 틀리는지 나눠 본다. v2 결과: '에어컨을 켜 달라는 말'은 speech 0.695로 맞았고(2위 0.650), '사람이 말하는 목소리'는 beep 0.654가 1위로 틀림. 즉 소리의 종류(말소리인지)보다 말에 들어 있는 단어와 가까운 질의를 더 잘 찾는다. 파일 3개, 합성 음성 1개라 잠정 결론. 2회차 408 ms, GPU 최대 1.13 GB.
- 실행: `python test_audio.py`

### measure.py — 6단계 성능 측정

3~5단계 값은 재는 방법이 제각각이라(텍스트는 GPU 메모리 없음, 사진은 첫 호출 포함) README 6단계 표를 같은 방법으로 다시 채우는 파일이다.

- 구성 4가지(텍스트 전용 / +비전 / +오디오 / 전체)마다 이 파일을 새 프로세스로 다시 실행해 모델을 새로 올린다. 앞 구성의 메모리가 섞이지 않게 하려고.
- 재는 값: 로드 후 장비 RAM(MB, 괄호는 로드 전보다 늘어난 양), 지연 1·2회차(표에는 2회차), 2회차 동안 GPU 사용률 평균/최대(%), GPU 메모리 최대(GB).
- RAM은 /proc/meminfo, GPU 사용률은 sysfs의 GPU load 파일을 읽기만 한다. sudo가 필요 없고 장비에 영향이 없다. load 파일을 못 찾으면 tegrastats 값으로 적으라고 안내한다.
- 입력은 3~5단계와 같다: 3단계 질의 2개, media/의 사진, clip.mp4(PyAV로 1초 1장), wav(librosa로 16 kHz 모노). 파일 읽기 시간은 지연에서 뺀다.
- 결과 표를 화면에 찍고 ~/eg2-lab/results_step6.md로 저장한다(보고서에 붙여 넣기용).
- 실행: `python measure.py` (전부, 5~10분) 또는 `python measure.py audio` (한 구성만: text / vision / audio / full)

### data/train.jsonl, data/eval.jsonl — 7단계 학습·평가 데이터

README 7단계 형식 그대로 한 줄에 `{"anchor": 질의, "positive": 정답 문서}` 하나다. 문서마다 교육생 말투의 질의가 3개씩 붙어 있고, 질의는 문서와 겹치는 단어를 일부러 줄였다.

- train.jsonl: 282쌍, 문서 94개. CO2·환기 14, 냉난방 13, 공기질 12, 센서·네트워크 12, 경보 11, 에이전트 11, 엣지 운영 11, 과정 운영 10.
- eval.jsonl: 60쌍, 문서 20개. 온도·습도·PM2.5·조도·소음·TVOC·재실 인원·냉난방·환기·센서 관리·경보·에이전트 권한.
- 평가 문서·질의는 학습 파일에 한 줄도 없다(만들 때 자동 검사). 학습에서 본 문장으로 시험하면 점수가 부풀기 때문이다.
- 수치는 실습용 가상 운영 기준이다. 3단계 test_text.py의 CO2·에어컨·Jetson 문장은 학습 데이터에 들어 있어서, 학습 후 3단계 결과는 '일반 성능' 확인용으로 쓰기 어렵다. 일반 성능은 eval_ir.py의 일반 문장 8쌍으로 본다.

### eval_ir.py — 7단계 검색 성능 평가 (학습 전후)

질의 60개마다 문서 20개를 유사도 순으로 줄 세우고, 정답이 몇 등인지로 점수를 낸다. 같은 파일을 원본 모델과 학습한 모델에 각각 돌려 비교한다. train_ft.py가 이 파일의 `build_evaluator()`를 불러 쓰므로 같은 폴더에 둔다.

- 점수: accuracy@1(정답이 1등인 비율), accuracy@3(3등 안), ndcg@10(정답이 위에 있을수록 큰 점수, 1등이면 1.0).
- README보다 더 재는 것: 256·128차원 점수(학습 후에도 짧은 벡터가 쓸 만한지)와 강의실과 관계없는 일반 문장 8쌍 점수(학습 때문에 일반 능력을 잃지 않았는지).
- 결과를 화면에 찍고 ~/eg2-lab/results_step7.md 끝에 덧붙인다. 실행할 때마다 한 묶음씩 쌓인다.
- 실행: `python eval_ir.py`(원본) / `python eval_ir.py models/eg2-classroom`(학습 후). 1분 안쪽.

### train_ft.py — 7단계 미세 조정 학습

train.jsonl로 텍스트 모델을 3 epoch 학습하고 models/eg2-classroom에 저장한다. 배치 안의 다른 문서를 오답으로 쓰는 MultipleNegativesRankingLoss를 MatryoshkaLoss로 감싸 768/512/256/128차원을 함께 학습한다.

- 준비: `pip install -c ~/eg2/torch-pin.txt datasets accelerate`(내 venv에만 설치, 장비 전체에는 영향 없음).
- README와 다른 점 세 가지. ① 가중치를 float32로 보관하고 계산만 bfloat16으로 한다. bfloat16 가중치는 유효 숫자가 3자리 정도라 2e-5 크기의 수정이 반올림으로 사라질 수 있다. ② float32로 늘어난 메모리를 줄이려고 단어 임베딩 표를 고정한다. ③ 중간 체크포인트를 저장하지 않는다(수 GB, 마지막 모델만 필요).
- 맨 위 설정(TRAIN_DTYPE, FREEZE_EMBEDDINGS, EPOCHS, BATCH, ACCUM, LR)만 바꿔 실험한다. OOM이면 BATCH 4, ACCUM 4. 평가 점수가 학습 중에 떨어지면 EPOCHS 1~2 또는 LR 1e-5.
- 출력: 학습할 가중치 수, epoch마다 loss와 평가 점수, 마지막에 학습 시간(분)과 GPU 메모리 최대.
- 실행: `nohup python train_ft.py > train.log 2>&1 &`, 진행은 `tail -f train.log`(Ctrl+C로 보기만 끝냄, 학습은 계속). 끝나면 README Q10처럼 `jobs`와 `ls -lh models/eg2-classroom`로 확인.

### app.py — 8단계 웹캠 물체 검출과 웹 검색

- 준비: `pip install -c ~/eg2/torch-pin.txt ultralytics lap fastapi "uvicorn[standard]" "git+https://github.com/ultralytics/CLIP.git"`(내 venv에만 설치). lap은 추적, CLIP은 YOLOE가 쓰는데, 미리 넣지 않으면 실행 중에 ultralytics가 torch 고정 없이 자동 설치하려 한다.

- 크롭은 crops/<mode>/에 쌓이고, 크롭마다 crops/<mode>/labels.csv에 파일 이름·YOLO 라벨·신뢰도·최종(재)라벨·점수·시각이 한 줄씩 기록된다(v4). 실행을 다시 해도 지워지지 않으니 필요 없으면 `rm -r crops/yolo`처럼 지운다.

### pose_model.py — 9단계 공통 모듈

pose_app.py와 train_pose.py가 같은 계산을 쓰도록 모아 둔 파일이다. 직접 실행하지 않고 같은 폴더에 두기만 한다.

### pose_app.py — 9단계 사람 동작·행동 인식 웹 앱

### train_pose.py — 9-6단계 GRU 학습

`--data` 폴더의 CSV 파일마다 라벨 하나(파일 이름)로 보고, 프레임을 윈도(동작 30, 행동 80프레임)로 잘라 작은 GRU를 처음부터 학습한다. 각 녹화의 앞 80%는 학습, 뒤 20%는 검증에 쓰고, epoch마다 검증 정확도를 출력한 뒤 혼동 행렬(무엇을 무엇으로 헷갈렸는지)을 보여 주고 최고 검증 정확도의 가중치를 저장한다.

- 실행: `python train_pose.py --data data/action --task action --window 30 --out models/action.pt`, 행동은 `--data data/behavior --task behavior --window 80 --stride 10 --out models/behavior.pt`.
- 라벨(CSV 파일)이 2개 이상 필요하고 `idle.csv`를 꼭 포함한다. Jetson GPU에서 수 분 안에 끝난다.
- v2: 행동 데이터처럼 짧은 통과를 여러 번 녹화한 경우 `--split seq`(통과 20%를 통째로 검증)를 쓴다. 약 12 fps 환경에서는 행동 윈도를 README의 80 대신 40으로 줄인다: `python train_pose.py --data data/behavior --task behavior --window 40 --stride 5 --split seq --out models/behavior.pt`.

### prox/ 폴더 — 10단계 카메라 2대 접근 감지

10단계 파일은 모두 `~/eg2-lab/prox/` 에 두고 그 폴더에서 실행한다(`import stereo`가 같은 폴더를 찾기 때문). 보정 결과는 `prox/calib/`에 쌓인다. 좌표계는 강의실 바닥 기준: 원점 = 칠판 왼쪽 아래 바닥, x = 칠판 방향(오른쪽 +), y = 교실 뒤쪽(+), z = 높이, 단위 m.

#### prox/stereo.py — 10단계 공통 모듈

직접 실행하지 않는다. v2부터 `open_source`·`read_frame`·`cam_name`(USB 장치 번호와 IP 카메라 rtsp 주소를 같은 방식으로 열고, 큰 화면은 640x480으로 줄임), `load_cam`(calib/camN.npz 읽기), `undistort`(렌즈 왜곡 보정), `triangulate`(두 카메라 픽셀 → 3D 점 + 재투영 오차), `ray_plane`(카메라 1대: 높이를 가정해 위치 추정), `upper_body`(어깨 중심, 없으면 코), `ankle`(발목, 10-3용), `match_people`(재투영 오차가 작은 순으로 두 카메라 사람 1:1 매칭), `Kalman2D`·`relative_state`(10-8 이동 타겟)를 제공한다. v1은 README 코드와 같고 주석만 추가했다. v2: 지원 님 장비(USB 웹캠 1대 + IP 카메라 1대)에 맞춰 카메라 열기 함수 추가.

#### prox/calib_intrinsics.py — 10-1 렌즈 보정

카메라 장치 번호마다 한 번씩 실행한다. 체커보드를 화면 가장자리·모서리까지 기울여 가며 천천히 움직이면 1초 간격으로 서로 다른 위치 20장을 모아 `calib/cam<번호>_intr.npz`를 저장하고 재투영 RMS를 출력한다(0.5px 이하 양호, 1.0 이상 재촬영). 모니터가 없어도 되며, 마지막으로 잡힌 사진은 `calib/cam<번호>_last.jpg`로 확인한다.

- 옵션: `--cam`(필수), `--cols 9 --rows 6`(내부 코너 수), `--square 0.025`(칸 길이 m, 인쇄 후 자로 재서 다르면 바꾼다), `--n 20`.
- README와 다른 점(v1): 끝나거나 Ctrl+C 때 카메라를 닫고, 5초 동안 체커보드를 못 찾으면 안내를 출력한다.
- v2: `--cam "rtsp://아이디:비번@주소/경로"`로 IP 카메라도 보정한다. 결과 파일은 `calib/camip_intr.npz`.
- v3: 실행 중 맥북 브라우저에서 `http://<JETSON_IP>:8010`으로 카메라 화면을 본다(찾은 꼭짓점 초록 표시, 모은 장수, NO BOARD 빨강). 포트가 겹치면 `--port 8011`.
- v4: 보드가 멈춰 있을 때만 찍는다(미리보기 노랑 HOLD STILL = 움직이는 중). 이미 찍은 위치를 파란 점으로 표시. 계산 후 사진별 오차를 출력하고 유독 큰 사진을 빼고 다시 계산한다.
- v5: 꼭짓점 정밀화 창을 칸 크기에 맞춤, 왜곡 k3 고정(`--k3`로 해제). 찍은 원본을 `calib/cam<이름>_imgs/`에 저장하고 `--from-dir calib/camip_imgs`로 다시 찍지 않고 재계산.

#### prox/calib/world_points.json — 10-2 기준점 좌표

두 카메라 모두에 보이는 기준점 8개 이상(계산용 6개 이상 + `"check": true` 검증용 2개 이상)의 실제 좌표. 바닥(z=0)·책상(z≈0.74)·벽(z≈1.5)처럼 높이가 다른 점을 섞는다. 2026-10-28 지원 님 실측값(8점, 검증용 F2·D3)으로 교체. `_카메라_실측`(카메라 위치 줄자값)과 `room`(proximity_app이 사람 위치로 인정하는 바닥 범위)도 들어 있다. 2026-10-30 장소 변경으로 새 실측값(14점: 바닥 A~H, 의자 a~d, 벽 e·f, 검증용 C·d, 카메라 cam0 (0,0,1.45)·cam1 (0,1.40,1.45))으로 다시 교체. 이전 값은 `world_points_이전장소.json`.

#### prox/preview_cams.py — 10-2 준비, 두 카메라 실시간 미리보기

`python preview_cams.py --cams 0 'rtsp://...'` 실행 후 맥북 브라우저 `http://<JETSON_IP>:8010`. 두 카메라 영상을 좌우로 붙여 보여 주고, 가운데 빨간 십자(+)가 카메라 정면이다. 카메라 방향을 맞출 때 쓴다. 아무것도 저장하지 않는다. (2026-10-28 v1)

#### prox/ptz.py — IP 카메라 방향 돌리기 (ONVIF)

`python ptz.py left 0.3` (방향 left/right/up/down, 숫자 = 도는 시간 초). 회전형 IP 카메라는 손으로 돌리면 기어가 상할 수 있고 VIGI 앱 목록에도 없어서, ONVIF(포트 2020)로 명령을 보낸다. 비밀번호는 실행할 때 입력. preview_cams.py를 켜 둔 채로 다른 터미널에서 쓴다. 10-2 이후에는 쓰지 않는다. (2026-10-28 v1, 2026-10-30 실제 카메라에서 동작 확인)

#### prox/calib_extrinsics.py — 10-2 카메라 위치 보정

두 카메라 스냅샷을 웹으로 보여 주고, 드롭다운에서 기준점을 고른 뒤 각 이미지에서 그 점을 클릭하게 한다. 클릭은 `calib/clicks.json`에 저장돼 다시 실행해도 남는다. **계산**을 누르면 solvePnP로 카메라별 위치(`pos`)·평균 재투영 오차(`mean_px`, 3px 이하 목표)·기준점별 3D 오차(`verify`, cm)를 보여 주고 `calib/cam0.npz`, `calib/cam1.npz`를 저장한다.

- `--cams 0 2`의 순서가 cam0, cam1이 된다. v2부터 IP 카메라는 주소로 쓴다: `--cams 0 "rtsp://..."`. 이후 proximity_app.py에도 같은 순서로 쓴다.
- 카메라를 조금이라도 움직이면 다시 해야 한다(클릭은 남아 있으므로 새 스냅샷 → 다시 클릭 → 계산).
- README와 다른 점(v1): Ctrl+C로 바로 꺼지도록 timeout_graceful_shutdown=1.
- v3 (2026-10-28): 좌표계 규칙을 '원점에서 x를 바라볼 때 y가 왼쪽, z는 위'로 바꿈(README 방향은 왼손 좌표계라 계산이 깨짐). 기준점이 카메라 뒤쪽으로 계산되면 결과에 `warning`을 표시한다.
- v4 (2026-10-28): 첫 계산을 SOLVEPNP_SQPNP로(기준점이 좁은 영역에 몰려 있을 때 ITERATIVE가 엉뚱한 답으로 빠지는 문제, 시뮬레이션 확인). `_카메라_실측`이 있으면 `pos_vs_measured_cm`(계산 위치와 줄자 위치 차이)을 함께 보여 준다.

#### prox/proximity_app.py — 10-3~10-8 접근 감지 웹 앱

두 카메라에서 관절을 찾고(YOLO11n-pose) 사람의 바닥 위치를 구해 타겟까지의 거리 변화로 접근 시작·근접 알람(`--near`, 기본 1.0m)·이탈 알람(`--far`, 기본 3.0m)을 낸다. 화면: 카메라 영상 2개, 평면도, 사람 표(거리·추세·구역·자세·방식), 기록, 상단에 fps·카메라 시간 차·RAM.
- v3 (2026-10-28): `world_points.json`에 `room`이 있으면 그 범위를 사람 위치 허용 범위로 쓴다(기준점이 좁은 영역에 몰려 통로의 사람이 버려지는 문제).

- `--mode ankle1`(카메라 1대 + 발목, 10-3) / `stereo`(어깨 삼각측량, 10-4) / `fused`(기본, + 카메라 1대 추정, 10-5).
- 타겟: `--target-xy 3.0,1.0`(줄자로 잰 바닥 좌표) 또는 `--target "red fire extinguisher"`(YOLOE 후보 → EmbeddingGemma 2로 고름 → 삼각측량, 10-6). `--moving`(10-8)은 타겟도 매 프레임 추적해 칼만 필터로 속도를 추정하고 TTC(충돌 예상 시간)가 `--ttc`초 미만이면 충돌 위험 알람.
- v2: `--cams 0 "rtsp://..."`로 IP 카메라 사용, `--lag 0 300`처럼 카메라별 영상 지연(ms)을 빼서 두 카메라 시각을 맞춘다(IP 카메라는 USB보다 수백 ms 늦게 도착).
- 사람 이미지는 저장하지 않는다. 타겟 후보 물체 크롭만 `calib/target_cand*.jpg`, `calib/reid*.jpg`에 저장된다.
- README와 다른 점(v1): quantize=16, Ctrl+C 정상 종료(카메라 스레드까지 정리), 화면 상단에 이 프로세스 RAM(MB) 표시(10-7 표용), ~/eg2-lab에 받아 둔 yolo11n-pose.pt·yoloe-11s-seg.pt 재사용, 이미지 임베딩 호출 방식을 8단계와 맞춤. 파일 맨 위 수정 기록 참고.
- 공용 장비 주의: 카메라 2대를 이 프로그램이 모두 차지한다. 포트 8000을 다른 학생이 쓰면 `--port 8001`.

#### prox/find_rtsp.py — IP 카메라 주소 찾기

VIGI 앱에서 카메라 IP를 확인할 수 없을 때 쓴다. Jetson의 사설 IP 대역(예: 172.27.0.0/16)을 자동으로 찾아 모든 주소의 554번 포트에 연결을 시도하고, 응답한 기기의 IP와 MAC 주소를 출력한다. 카메라 스티커의 MAC과 같은 줄이 카메라다. 연결만 시도하고 아무것도 바꾸지 않는다. 대역이 크면 1~2분 걸리고, `python find_rtsp.py 172.27.57.0/24`처럼 범위를 직접 줄 수도 있다. 대역이 /16보다 크면(학교 free 와이파이는 172.24.0.0/14) /16씩 나눠 실행한다. v2: `--port 443`으로 카메라 웹 설정 포트도 찾을 수 있다.

## 폴더 구조와 eg2 단축 명령

가상환경 ~/eg2와 실습 폴더 ~/eg2-lab은 홈 폴더에 나란히 있는 별개의 폴더다. ~/eg2는 설치된 패키지(공구함), ~/eg2-lab은 우리가 쓴 코드(작업대)다.

```text
/home/<USER>/
├── eg2/            가상환경: Python + torch, sentence-transformers 등
│   └── bin/activate  ← source로 켜는 파일
└── eg2-lab/        실습 폴더: 우리가 쓴 코드
    ├── check.py
    ├── eg2.py
    ├── test_text.py
    ├── test_vision.py
    ├── make_sounds.py
    ├── test_audio.py
    ├── measure.py
    ├── results_step6.md  6단계 measure.py가 만드는 결과 표
    ├── eval_ir.py
    ├── train_ft.py
    ├── results_step7.md  7단계 eval_ir.py가 덧붙이는 결과 표
    ├── train.log     7단계 학습 로그
    ├── data/         7단계 train.jsonl, eval.jsonl
    ├── models/eg2-classroom/  7단계 학습한 모델 (텍스트 전용)
    ├── runs/         7단계 학습 임시 폴더
    ├── app.py
    ├── yolo11n.pt, yoloe-11s-seg.pt  8단계 검출기 가중치 (첫 실행 때 자동 다운로드)
    ├── crops/        8단계 app.py가 저장한 물체 크롭 (crops/yolo, crops/relabel, crops/yoloe)
    ├── pose_model.py, pose_app.py, train_pose.py  9단계
    ├── yolo11n-pose.pt  9단계 관절 추정 가중치 (첫 실행 때 자동 다운로드)
    ├── data/action/, data/behavior/  9-3 녹화 CSV (파일 이름 = 라벨). action: idle, wave, clap, arms_crossed, raise_both, raise_one
    ├── models/action.pt, models/behavior.pt  9-6 학습한 GRU 모델

/ssd/hf/            공용 모델 폴더 (HF_HOME, 모든 계정이 함께 사용)
```

- `source ~/eg2/bin/activate`는 폴더를 이동하지 않는다. 이 터미널의 `python`이 ~/eg2 안의 Python을 가리키게 바꿀 뿐이다. 켜지면 프롬프트 앞에 `(eg2)`가 보인다.
- `eg2` = `source ~/eg2/bin/activate && cd ~/eg2-lab`. user_setup.sh가 ~/.bashrc에 등록한 단축 명령으로, venv 켜기와 실습 폴더 이동을 한 번에 한다.
- 등록 전에 열어 둔 터미널은 `eg2`를 모를 수 있다. `source ~/.bashrc`로 설정을 다시 읽게 하면 된다.
- 맥북에서 파일을 보낼 때는 내 계정의 실습 폴더로: `scp test_text.py <USER>@<JETSON_IP>:~/eg2-lab/` (aip-1@로 보내면 관리자 계정에 들어간다).
